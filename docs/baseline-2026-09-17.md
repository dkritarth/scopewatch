## What works

The UI displays three invented runs with task scope, chronological events, action and
policy labels, and selected evidence. Status and text filters intersect and persist
across run changes. Empty results clear evidence; reset restores events. Missing traces
stay unavailable, and fixture-authored summaries are labeled separately. There are no
approval or execution controls and no connection to the Python PoC.

The Python PoC captures supported exposed reasoning fields or synthetic tagged input,
validates auditor output and grounded excerpts, and returns fallback HOLD on failures.
Local diagnostic codes distinguish failure boundaries without echoing provider error
text. A valid model HOLD is distinct from fallback HOLD. Evaluation reports omit traces
and explanations; the report checker uses committed expectations, rejects missing or
duplicate cases and diagnostics, and does not trust report-supplied match counts.

## Repeatable validation

From the repository root, using Python 3.12 and Node 22 or newer:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r poc/cot-auditing/requirements.txt
.venv/bin/python -m pytest poc/cot-auditing -q
.venv/bin/python -m compileall -q poc/cot-auditing/src poc/cot-auditing/scripts
npm ci --prefix frontend
npx --prefix frontend playwright install chromium
npm test --prefix frontend
npm run test:browser --prefix frontend
for file in frontend/scripts/*.js frontend/tests/*.js frontend/tests/browser/*.js; do
  node --check "$file" || exit 1
done
git diff --check
```

On Debian/Ubuntu, creating a venv requires the matching `python3-venv` package.
This host lacked ensurepip, so validation used an existing isolated Python 3.12.3
environment with pytest and Pydantic installed. Local Node was 24.19.0; CI uses Node 22.
Linux Chromium dependencies can be installed with Playwright's `--with-deps` option,
as in CI. Dependency/browser installation requires network access; tests use synthetic
fixtures and mocks and require neither model credentials nor live model calls.

The browser test exercises every fixture event, run/event keyboard focus retention,
scope text, intersecting filters, empty evidence, reset, and selection retention. It
checks horizontal overflow at 320, 390, 768, and 1440px in light and dark modes, with
reduced motion enabled. It records page/console errors and blocks non-local page
requests. The server binds an ephemeral loopback port and is closed with the browser
in cleanup. This is an automated smoke test, not a screen-reader or visual-design audit.

The offline evaluator was also run without `--live`. It matched 3 of 6 development
cases and exited 1; the saved-report checker also exited 1. The mismatches remain
`blocked-config`, `reject-unsafe-read`, and `scope-forgery`. Passing structural tests
does not make the keyword mock an accurate scope auditor. The report was kept outside
the repository, and no model call was made.

## Limits and handoff

- No integrated agent runtime, upload workflow, authentication, authorization
  enforcement, or pre-execution gate exists. Neither prototype prevents actions.
- No Nemotron/Nebius integration or hackathon infrastructure requirement is satisfied
  by these changes. No paid/live model experiment or external deployment was run.
- Provider-exposed text is not proof of complete internal reasoning. Captured text,
  summaries, observations, and inferred intent must not be treated as interchangeable.
- The report checker checks consistency with fixtures, not authenticity of a model run.
  Diagnostic codes identify an observed failure boundary, not guaranteed root cause.
- Screen readers, zoom, non-Chromium browsers, production traces, and held-out model
  accuracy remain unverified. Architectural choices still await team decisions.
- T3 PR registration remains outstanding for #8, the recovered #9/#10 work, and this
  handoff PR. No T3 PR-linking tool was exposed, and plugin discovery returned no T3
  connector. GitHub PRs and review comments are not substitutes for T3 registration.

Launch the synthetic UI with `npm run serve --prefix frontend`, then open
`http://127.0.0.1:4173`. Stop the loopback-only server with Ctrl+C. See each prototype's
README for its separate run instructions. Keep future live experiments explicitly
authorized and do not commit credentials, private traces, or runtime reports.
