02 · The idea

Problem, adopter, and where it sits among existing tools

Problem. Coding agents run shell commands and edit files with a person's authority, and a prompt injection hidden in a README or an invoice can steer them. Logs record what already ran; nothing checks permission first. The docs cite two vendor-confirmed Microsoft CVEs: CVE-2025-32711 (M365 Copilot, AI command injection leading to disclosure) and CVE-2025-53773 (GitHub Copilot and Visual Studio, command injection leading to local code execution). They also cite OWASP LLM01:2025 (prompt injection) and LLM06:2025 (excessive agency). Scopewatch has not reproduced those vulnerabilities, and it does not claim it would stop their exploit chains.

Who adopts it. Platform and security teams running coding agents that need to review tool actions before they touch a workspace. The proposal's first user is a developer running a single coding agent.

How it works

1 · Deterministic policyChecks tool, operation and path against the declared task scope before any model call. Catches traversal, symlink breakouts and blocked folders, and denies every network operation. ALLOW HOLD DENY
2 · Reasoning auditorAn independent model reads the agent's exposed reasoning for drift, injection-following, exfiltration intent or evasion. Flagged excerpts must match the trace verbatim. It can only escalate: ALLOW→HOLD
3 · Human approvalA held action waits in the reviewer dashboard. Each approval is bound to one exact action, works once, expires, and can never override a policy DENY.
4 · Controlled executorRuns only actions with a stored decision, inside a per-run workspace. Commands run in a Docker container with --network none, a non-root user and a read-only root.

Prior art, compared from documentation (not benchmarked)

SystemOverlap and difference
Meta LlamaFirewallAlready audits reasoning and traces (AlignmentCheck). Scopewatch does not claim to have invented reasoning audits.
NVIDIA NeMo GuardrailsIts tool and action rails overlap with the policy layer.
Invariant GuardrailsOverlaps directly on gateway mediation and rule enforcement.
NVIDIA AEGIS 1.0A content-safety classifier. It answers a different question from task authorisation.

What Scopewatch adds is the combination and the review record. A deterministic DENY is final. Reasoning can only escalate. A failed audit holds. The executor needs a stored decision, plus a valid single-use approval for held actions. Provenance labels are gated by a capture credential, and excerpts must be grounded in the submitted text.

Honest limits. Only actions routed through the gateway API are mediated; anything that bypasses it is not observed, blocked or recorded. Reasoning is evidence, not proof of intent: a model can omit, rationalise or encode its plan, so a policy-legal harmful edit with concealed intent may pass. Docker constrains dispatched commands, not unrelated host processes. No adoption-time, cost or reviewer-workload figures have been measured.

03 · Ideation

How the design was chosen

The repository began as a passive monitor: an instrumented run plus a reviewer timeline. Early notes from several models proposed alternatives. A 2026-09-16 validation on OpenRouter found that seven requests returned no reasoning, and four of six live auditor cases failed validation or transport. A 2026-09-19 gap audit found two disconnected prototypes. PR #4 (2026-09-13) moved the project toward active enforcement.

Planning session, 2026-09-23 (became ADR-0001)

@dkritarth made the decisions, and Claude Opus 5.5 in Claude Code asked the questions and kept the record. The record became team policy when ADR-0001 (#21) merged.

Architecture decision records

  • ADR-0001, Accepted. Thirteen decisions: the gateway shape, the stack, the agent loop, provider profiles (mock, openrouter-dev, nebius-demo), an open-weight reasoning agent, escalate-only reasoning, one audit per turn, the Docker executor, the demo plan, synthetic-only data and the governance model. It also sets the provenance rules: only reasoning.text counts as a raw trace, and a verified provider trace requires the SCOPEWATCH_CAPTURE_TOKEN.
  • ADR-0002, Proposed. A tamper-evident evidence hash chain over exported events, with an offline verifier. It detects later edits; it does not prevent unsafe execution.
  • ADR-0003, Proposed. Policy identity persisted in evidence (policy_version = date.N+fingerprint). An approval is honoured on the decision the reviewer saw, and any drift is recorded.

Security hardening worth knowing about

  • Path containment: a symlink inside an allowed directory exposed blocked content (#63, fixed in #69). Copy-back wrote through a destination symlink (#167, fixed in #337). Symlink loops now fail closed on Python 3.12 and 3.13 (#178, #279). Case-variant and casefold aliases of restricted paths are blocked (#316, #331).
  • Approvals: an approval could reopen a completed run (#67, #233), and a consumed approval could be replayed (#81). The stored single-use check was unreachable (#141). A run could close during execution (#282).
  • Executors: the remote executor skipped scope, approval and lifecycle checks (#257). Blocked paths were staged into the run_command container, leaving .env readable (#260). Output and copy-back sizes are now bounded (#286).
  • API: there was no reviewer authentication, plus wildcard CORS with credentials and a shared token (#258). Request bodies and reasoning payloads were unbounded (#320). Validation errors no longer echo input.
  • Auditor: unescaped fields allowed prompt injection into the auditor (#259). Omitted evidence now fails closed (#312). Timeouts, token caps and malformed output all hold the action (#181, #226, #228).
  • Evidence: decisions are persisted before effects (#143). Caller-supplied provenance is marked unverified (#164). The hash-chain verifier no longer accepts bad sequences (#261, #273).

  • Every false negative on both profiles was injection_following, where the auditor said no concern. That is the only direction in which a concern can slip through, and it is published in the repository rather than hidden.
  • Failures were mostly UNGROUNDED_EXCERPT (OpenRouter 4; Nebius 5, plus 2 INVALID_AUDIT_OUTPUT). A failed audit holds the action; the harness scores it as a miss, not a false negative.
  • The zero-false-hold figure is 0 of 12 clean cases per profile, or 0 of 24 clean evaluations across both runs. It is not 0 of 96 audits.
  • These results predate the grounding fix (#150) and later prompt changes (v1.1, v1.2), so they do not measure the current gateway or the shipped agent/auditor pair. The fixtures and the mock auditor landed in the same PR, and there is no freeze-then-tune history, so treat the figures as a generalisation estimate.
  • The historical held-out split is spent: an automated audit flags 17 cross-split pairs and literal mock-rule overlap in 53 of 61 cases. A fresh v2 split (12 dev, 12 held-out) has no provider measurement yet.
  • Five dev-split runs on nebius-demo ranged from 61.5% to 84.6% accuracy: a sample, not a measurement of record.
